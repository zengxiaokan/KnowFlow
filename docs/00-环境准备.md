# 00：环境准备

## 概念

Docker 把项目需要的 Web、Worker、PostgreSQL/pgvector 和 Redis 打包成彼此隔离、但可以通信的容器。这样 Windows 本机不用分别安装 PostgreSQL、Redis 或 Linux 版 Celery。`compose.yaml` 记录镜像、端口、环境变量、健康检查和数据卷，换电脑后也能复现。

| 服务 | 做什么 | 是否在浏览器中直接访问 |
| --- | --- | --- |
| `web` | Django、Daphne、页面、REST API、WebSocket 入口 | 是，8000 端口 |
| `worker` | Celery，解析、向量化、问答、工作流 | 否 |
| `db` | PostgreSQL + pgvector，保存业务数据与向量 | 否 |
| `redis` | Celery 消息队列、结果后端、Channels 消息层 | 否 |

## 本阶段目标

完成后，你能复制本机配置、启动四项服务、注册账号，并能根据日志判断是 Web、Worker、数据库还是模型配置的问题。

## 准备软件

1. 安装并启动 **Docker Desktop**，设置中启用 *Use the WSL 2 based engine*。
2. 准备浏览器；建议 Chrome 或 Edge。
3. 准备 DeepSeek Key（生成回答）和 SiliconFlow Key（BGE-M3 向量化）。真实 Docker 模式没有有效 Key 时，上传后的向量化或问答会失败，这是正常且可诊断的。
4. Git 不是启动必需，但强烈建议安装，以便查看改动和提交作业。

## 操作步骤

### 1. 进入项目根目录

在 PowerShell 中执行，所有后续命令都在此目录运行：

```powershell
cd D:\python\KnowFlow
Get-ChildItem compose.yaml,Dockerfile,.env.example,manage.py
```

第二条命令应列出四个文件；如果某个不存在，说明你没有进入项目根目录。

### 2. 创建 `.env`

`.env.example` 是可公开提交的模板；`.env` 才是你电脑上的真实配置和 Key，绝不提交到 Git。

```powershell
Copy-Item .env.example .env
notepad .env
```

首次运行时保留数据库和 Redis 默认配置，重点填写：

```dotenv
DEBUG=true
SECRET_KEY=替换为一串随机且不公开的字符
ALLOWED_HOSTS=localhost,127.0.0.1
DEEPSEEK_API_KEY=你的_DeepSeek_Key
SILICONFLOW_API_KEY=你的_SiliconFlow_Key
```

不要在 Key 两侧加引号或额外空格。Key 只由后端容器读取，不能写入模板、截图或浏览器 JavaScript。

### 3. 首次构建与启动

```powershell
docker compose up --build
```

第一次需要下载基础镜像与依赖，网络较慢时等待数分钟是正常的。看到 Web 出现 Daphne 启动日志、数据库与 Redis 变为 healthy 后，另开一个终端执行：

```powershell
cd D:\python\KnowFlow
docker compose ps
```

预期 `web`、`worker`、`db`、`redis` 都为 running，`db` 和 `redis` 显示 healthy。打开：

- 注册：`http://localhost:8000/accounts/signup/`
- 登录：`http://localhost:8000/accounts/login/`
- API 文档：`http://localhost:8000/api/docs/`

注册首个用户时，系统自动创建个人组织并授予 `owner` 身份。创建一个知识库、上传很小的 Markdown 文本，等待状态变为“已就绪”，这就是本阶段最小成功链路。

### 4. 停止、后台运行、看日志

```powershell
# 前台日志按 Ctrl+C 后，再停止容器；数据卷保留
docker compose down

# 后台运行，不占用当前窗口
docker compose up -d --build

# 定位运行问题
docker compose logs -f web
docker compose logs -f worker
```

`down` 不会删除数据；但 `docker compose down -v` 会删除数据库、Redis 和上传文件卷。除非已有可恢复备份，否则不要加 `-v`。

## 编码任务

练习增加一个环境变量 `SITE_TITLE`：

1. 在 `.env.example` 添加 `SITE_TITLE=KnowFlow`。
2. 在 `config/settings.py` 用已有的 `env()` 函数读取它。
3. 在基础模板显示它，不要在 HTML 中硬编码。
4. 执行 `docker compose up -d --build web worker` 并刷新页面验证。

你会借此理解“代码默认值、可提交样例、机器私密配置”三者的差别。

## 验收清单

- [ ] `docker compose ps` 中四项服务都在运行。
- [ ] 注册、登录和 API 文档页面可打开。
- [ ] 能创建知识库并上传一份小文档。
- [ ] `docker compose exec web python manage.py check` 无错误。
- [ ] `git status` 不显示 `.env`。

## 常见错误

| 现象 | 检查方法 | 处理方式 |
| --- | --- | --- |
| `localhost:8000` 拒绝连接 | `docker compose ps` | 先看 `docker compose logs web` |
| 构建卡在下载 | Docker 网络、镜像源 | 等待；检查 Docker Desktop 代理/镜像源，别反复取消 |
| `db` 不 healthy | `docker compose logs db` | 不要直接删卷；先判断是否为旧数据与新密码不匹配 |
| 上传一直失败 | `docker compose logs -f worker` | 检查两个 API Key、网络和 Worker 是否运行 |
| 8000 被占用 | 日志含 address in use | 将 `compose.yaml` 的 `8000:8000` 改为 `8001:8000` |
