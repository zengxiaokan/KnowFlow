# 08：工作流领域模型

## 概念

工作流把一次可重复的“输入 → 查资料 → 组织提示词 → 调模型”保存为版本化定义。首版特意采用**线性流程**，不做拖拽画布、分支、循环或任意代码执行：简单边界更容易理解、测试和授权。

一个 `Workflow` 是稳定业务对象；一个 `WorkflowVersion` 保存某次 JSON 定义；每次 `WorkflowRun` 固定指向一个已发布版本；每个节点产生一条 `WorkflowStepRun`。所以即使未来编辑流程，旧运行仍可回答“当时用的是哪一版配置”。

## 本阶段目标

会通过表单创建并运行工作流；理解四类节点的输入输出；能在运行详情定位失败节点，并知道当前 UI 与底层能力的边界。

## 四类节点

| 类型 | 作用 | 输出示例 |
| --- | --- | --- |
| `input` | 从运行表单读取值 | `"Java 并发"` |
| `retrieve` | 在绑定知识库中检索相关 Chunk | 多段拼接的资料正文 |
| `prompt` | 使用 `{{ variable }}` 渲染文本模板 | 渲染后的提问指令 |
| `llm` | 调用聊天 Provider 生成文本 | 模型回答 |

变量引用使用 `{{ key }}`。例如 `retrieve` 节点可查询 `{{ input }}`，LLM prompt 可使用 `{{ context }}` 和 `{{ input }}`。未定义变量会渲染为空字符串，因此变量名拼错往往会造成“模型回答很空”，应在运行详情检查每一步输入输出。

## 操作步骤

### 1. 用页面创建第一个流程

进入“工作流”，填写：

1. 名称：`资料摘要`。
2. 知识库：选择一个包含已就绪文档的知识库。
3. 输入变量名：保留 `input`。
4. 提示词模板：`请仅根据以下资料，围绕 {{ input }} 输出三条结论。资料：{{ context }}`。
5. 勾选“先检索绑定知识库”。
6. 保存工作流，输入一个主题并运行。

当前表单会自动生成 `input → retrieve（可选）→ llm` 的定义。**勾选检索后，提示词必须显式写入 `{{ context }}`，LLM 才会收到检索结果；只写 `{{ input }}` 仍能运行，但不会使用资料。** 表单没有单独暴露 `prompt` 节点，是为了让新手不用手写 JSON；底层 `validate_definition()` 和执行器仍支持 `prompt` 节点，供 REST/API 或后续高级编辑器使用。

### 2. 理解版本与运行

创建时服务会在同一事务中建立 `Workflow` 和编号为 1、`is_published=True` 的版本。运行时只寻找已发布版本，保存原始 `input_data`，然后投递 `execute_workflow`。Worker 顺序执行节点：每一节点先创建 `WorkflowStepRun(status=running)`，成功后写入输出；任一步异常则流程状态为 failed，并记录错误文本。

### 3. 查看失败和重试

打开运行详情，按顺序看每个步骤的类型、状态、输入、输出和错误。失败运行可点击重试；系统会删除该运行原有步骤记录，清空输出与错误，将状态重置为 pending，再在**同一个 WorkflowRun** 上重新执行。成功运行不会允许重复执行。

## JSON 示例（高级阅读）

下面定义展示了全部四种节点，适合从 API/测试中理解，不建议新手直接修改生产数据库：

```json
{
  "nodes": [
    {"key": "topic", "type": "input", "input_key": "topic"},
    {"key": "context", "type": "retrieve", "query": "{{ topic }}", "limit": 4},
    {"key": "instruction", "type": "prompt", "template": "根据资料总结：{{ context }}"},
    {"key": "answer", "type": "llm", "prompt": "{{ instruction }}"}
  ]
}
```

## 编码任务

增加一个“默认输入值”能力：仅对 `input` 节点新增 `default`；在 `_execute_node()` 读取；在表单和运行页显示；写测试覆盖“未提供输入时用默认值”和“用户提供值覆盖默认值”。不要增加 Shell、Python 或任意 URL 回调节点——这会让工作流越过权限边界，变成远程执行器。

## 验收清单

- [ ] 能创建绑定知识库的线性工作流。
- [ ] 能成功运行，并在详情看到每个步骤的输入输出。
- [ ] 绑定知识库不可访问时，运行被拒绝。
- [ ] LLM 步骤生成模型用量记录。
- [ ] 失败后能定位具体失败步骤并重试。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 检索节点报错 | 没有绑定知识库 | 选择知识库或移除 retrieve 节点 |
| 变量为空 | 模板 key 拼错 | 在运行详情核对前序节点 key |
| 没有运行权限 | 账号是 viewer | 使用 owner/editor 账号 |
| 想在 UI 中添加 prompt 节点 | 当前表单只生成简化流程 | 先理解 JSON/API；不要手改数据库 |
