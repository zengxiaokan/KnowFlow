# 10：权限与数据隔离

## 概念

KnowFlow 是多租户系统。**组织是第一层隔离边界，知识库授权是第二层边界。** UI 隐藏按钮只改善体验，不是安全措施；真正的安全检查必须存在于 Django View、DRF `get_queryset()`、文件下载、WebSocket 握手、异步任务启动和服务层。

系统不区分一个单独的“超级管理员”业务角色。Django `is_superuser` 可进入 `/admin/` 做系统维护；日常产品内的最高权限是组织 `owner`。这能避免把“平台运维权限”和“某个企业资料权限”混为一谈。

## 本阶段目标

理解组织角色和知识库角色的边界；会创建第二个账号验证允许与拒绝；修改功能时知道应该在哪里补权限，而不是只改前端。

## 权限矩阵

| 身份 | 组织内可见知识库 | 仅授权成员知识库 | 典型能力 |
| --- | --- | --- | --- |
| Django superuser | 通过 Admin 维护全局数据 | 不应作为普通产品访问模型依赖 | 系统运维、后台管理 |
| Organization owner | 可见、可管理、可删除 | 可见、可管理、可删除 | 成员、邀请、角色、所有知识库 |
| Organization editor | 可见、可管理 | 仅被授予 Manager 时可管理 | 创建资料、文档、组织内工作流 |
| Organization viewer | 可见但不能管理 | 仅被授予 Reader/Manager 时可读 | 查看允许范围内的资料 |
| KB manager | 由组织成员身份前提决定 | 可管理被授权的 KB | 文档、设置、成员授权 |
| KB reader | 由组织成员身份前提决定 | 可读被授权的 KB | 阅读、问答（视页面能力） |

`KnowledgeBase.access_scope` 可为 `organization` 或 `restricted`。`visible_knowledge_bases(user)` 集中实现可见性：用户必须先属于组织，组织内可见库可访问；受限库只允许 KB 成员或组织 owner。

## 操作步骤

### 1. 建立安全测试场景

准备三个账号：

- A：组织 owner；
- B：同一组织 viewer；
- C：另一组织 owner。

用 A 创建一个组织内可见知识库和一个“仅获授权成员”知识库；在受限库设置中仅给 B 赋 Reader。然后分别登录 B、C 验证：

1. B 能看到组织内可见库。
2. B 仅在被授权后能看到受限库；Reader 不应有删除、上传或授权按钮。
3. C 看不到 A 的任何知识库、任务、会话、文件或工作流。

不要只看导航列表；复制详情 URL、下载 URL、任务 WebSocket URL 都要测试。越权结果应是 404/403 或连接关闭，而不是把对象内容返回再由前端隐藏。

### 2. 团队邀请与审计

Owner 在团队页面可以生成邀请链接并指定 owner/editor/viewer。邀请对同一组织与邮箱的未接受记录去重，默认七天过期；接受后创建 `Membership`，并写入 `AuditLog`。团队页可调整角色、移除成员；审计日志页记录上传、删除、邀请、角色变更、工作流运行等事件。

邀请链接相当于短期凭证：不要复制到公开聊天群，不要在截图中暴露真实 token。过期或已接受链接不能再次用于加入。

### 3. 新增页面时的权限检查清单

以“查看文档切片”页为例：

1. URL 参数只当作候选 ID，不能直接 `Document.objects.get(pk=id)`。
2. 先通过 `get_visible_knowledge_base(user, kb_id)` 或等价 queryset 锁定租户。
3. 再查询该知识库下的 Document/Version。
4. 写操作额外调用 `can_manage_knowledge_base()`；删除知识库调用 `can_delete_knowledge_base()`。
5. API ViewSet 覆盖 `get_queryset()`，下载视图也做同样校验。
6. WebSocket Consumer 在 `connect()` 前调用数据库权限检查。
7. 添加跨组织、同组织无权限、正常访问三类测试。

## 编码任务

为一个新的“导出知识库”功能写权限设计再编码：导出属于读还是管理？受限库 Reader 是否允许？文件是否有时效链接？审计中记录谁导出了什么？先回答这些问题，再创建 URL 和页面。实现后必须用 A/B/C 三账号回归测试。

## 验收清单

- [ ] 组织 owner、editor、viewer 的页面按钮和后端行为一致。
- [ ] 受限知识库只有 owner 和显式 KB 成员可见。
- [ ] 猜测其他组织 ID 不能读取对象、下载文件或订阅 WebSocket。
- [ ] 文件下载由鉴权 View 提供，不直接公开媒体目录。
- [ ] 邀请、成员变更、文档与工作流关键行为有审计记录。

## 常见错误

| 错误 | 风险 | 修正 |
| --- | --- | --- |
| 只在前端隐藏“删除” | 直接请求 URL 仍可删除 | 后端每个写操作检查角色 |
| 只按对象 ID 查询 | IDOR 越权漏洞 | 查询从组织/可见知识库范围开始 |
| WebSocket 不做鉴权 | 可订阅他人进度和答案 | 握手前校验 user 与对象关系 |
| 将 `/media/` 完全公开 | 知识文件可被猜路径下载 | 使用鉴权下载视图或私有对象存储 |
