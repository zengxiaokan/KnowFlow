# 10：权限与数据隔离

## 概念

组织是租户边界；组织角色控制创建与管理。知识库可设为“组织内可见”或“仅获授权成员”，后者只允许 owner 或知识库成员关系中的 reader / manager 访问。

## 本阶段目标

任何读取都先限制组织，再检查知识库访问范围；任何写入都检查 owner、editor 或 knowledge-base manager。HTTP、REST API、文件下载与 WebSocket 握手使用同一套可见性规则。

## 操作步骤

阅读 permissions.py 以及 API ViewSet 的 get_queryset()。新建一个“仅获授权成员”知识库，通过 Django Admin 给指定组织成员添加 reader 或 manager 关系；再用两个账号手工尝试访问文档、任务和会话。

## 编码任务

使用团队页发出邀请。邀请 token 有七天有效期、按组织和邮箱去重、接受后写入 Membership 和 AuditLog。为受限知识库授予成员前，确认该用户已是同一组织成员。

## 验收清单

- URL 猜测 ID 不会泄露跨组织对象
- 未被授权的组织 viewer 看不到受限知识库、对应任务或工作流
- owner 可管理组织内所有知识库；editor 只可管理组织内可见知识库或被单独授予 manager 的受限知识库
- WebSocket 握手也做权限校验
- 文件下载由鉴权视图提供，而不是公开媒体目录

## 常见错误

不要只在前端隐藏按钮；前端不是权限边界。

## 延伸阅读

扩展到部门树、SSO、SCIM、审计日志和数据保留策略。
