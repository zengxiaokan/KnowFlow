# 04：文档解析与 RAG

## 概念

RAG（Retrieval-Augmented Generation，检索增强生成）不是把整份 PDF 塞进模型提示词，而是将资料变成可检索的切片：

```text
上传文件 → 提取文本 → 清洗/分段 → 切片 → Embedding → pgvector 入库
用户提问 → 问题向量化 → 余弦相似度检索 → 组织上下文 → 大模型生成带引用回答
```

好处是成本可控、响应更快、来源可以追溯，也能限制模型只使用当前知识库资料。代价是：切片质量、检索阈值和原文质量都会直接影响回答质量。

## 本阶段目标

能上传 PDF、DOCX、Markdown；理解当前的大小、页数、扫描件限制；能在页面查看切片，解释为什么一个文档要有多个 Chunk。

## 当前实现边界

| 项目 | 当前行为 |
| --- | --- |
| 支持格式 | `.pdf`、`.docx`、`.md`、`.markdown` |
| 单文件上限 | 20 MB，环境变量 `MAX_UPLOAD_BYTES` 可调整 |
| 批量上限 | 一次最多 20 个，环境变量 `MAX_BATCH_UPLOAD_COUNT` 可调整 |
| PDF 页数 | 最多 100 页 |
| 扫描 PDF | 不做 OCR；提取文本少于 20 字符时报 `scanned_pdf` |
| 目标切片大小 | 450 字符，`CHUNK_SIZE` 配置；最大 650 字符，`CHUNK_MAX_SIZE` 配置 |
| 重叠长度 | 60 字符，`CHUNK_OVERLAP` 配置 |
| 向量维度 | 1024，必须与 BGE-M3 Provider 匹配 |

## 操作步骤

### 1. 上传一份适合实验的 Markdown

新建一个 Markdown，含至少三个 `#`/`##` 标题，每个标题下写两段文字，再加一个超过 650 字符的段落。上传后等待状态“已就绪”，点击“查看切片”。

你应观察到：

- 每个 Chunk 有连续的 `ordinal` 序号；
- 标题会被保存为 Chunk 的 `heading`；连续的 PDF 对比表（如“特性 / ActiveMQ / RabbitMQ / RocketMQ / Kafka”）会被整理成独立的“指标：产品=值”切片，避免横向对比项被拆散；
- 切片优先在句子边界结束，超长句才按字符兜底拆分；
- 相邻块保留约 60 字符重叠，PDF 切片会显示真实起止页码；
- 当前版本才参与后续问答。

### 2. 阅读解析器

打开 `apps/knowledge/parsers.py`：

- PDF 使用 PyMuPDF 逐页提取文本，并插入页分隔标记；
- DOCX 使用 `python-docx` 读取非空段落；
- Markdown 用 UTF-8-SIG 解码，可兼容常见 BOM；
- 空文档、格式不支持、页数过多会抛出明确的领域错误。

再读 `apps/knowledge/chunking.py`：`normalize_text()` 统一换行和空白；切片函数识别 Markdown/编号标题、PDF 页码标记和句子边界；单个超长句才使用字符级兜底切分。

### 3. 理解为什么版本在索引成功后才切换

Worker 先生成新版本的全部向量，随后在同一个数据库事务中删除该版本旧切片、批量写入新切片、更新 `document.current_version` 和文档状态。失败时旧 `current_version` 不变，历史回答引用仍可还原。

### 4. 测试坏文件

依次尝试：扫描图片型 PDF、超过 100 页 PDF、空 `.md`、`txt` 文件。正确体验不是“服务器 500”，而是失败任务带清晰错误原因。不要上传真实敏感文件做公开调试。

## 编码任务

为切片补充一个安全的质量检查：例如拒绝去空白后少于 20 字符的 Chunk。完成时要同时：

1. 在切片函数中实现规则；
2. 确保整篇文档没有有效块时抛出 `DocumentParsingError`；
3. 增加单元测试；
4. 上传最小 Markdown 验证不会误杀正常资料；
5. 在页面展示的失败原因中使用用户能理解的中文。

## 验收清单

- [ ] PDF、DOCX、Markdown 都能形成 `ready` 文档和切片。
- [ ] 扫描 PDF 显示明确的不支持原因，而不是假装成功。
- [ ] 超页数、超大小和不支持后缀均有错误提示。
- [ ] 重传同一文档后出现新版本，旧引用没有丢失。
- [ ] 点击“查看切片”可看到标题、序号和正文。

## 常见错误

| 误解 | 实际情况 | 正确处理 |
| --- | --- | --- |
| PDF 能打开就一定能解析 | 图片扫描 PDF 没有文本层 | 上传可复制文字的 PDF，或后续单独接入 OCR |
| 切得越大越好 | 上下文噪声、费用和召回都会变差 | 保持 700/80 起点，用评测集再调参 |
| 改 Embedding 模型只改模型名 | 新旧向量可能维度或语义空间不同 | 新建索引版本并重算所有 Chunk |
| 重传要删除旧版本 | 历史消息来源会失效 | 保留版本，切换 `current_version` |
