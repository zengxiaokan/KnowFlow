# 11：部署与运维

## 概念

生产部署把应用、Worker、数据库、Redis 和文件存储视作独立的可观测组件。

## 本阶段目标

先在本机 Compose 可靠运行；上线时再增加 Nginx、HTTPS、对象存储、备份和日志告警。

## 操作步骤

生产前设置强随机 SECRET_KEY、DEBUG=false、严格 ALLOWED_HOSTS，并将 API Key 改为密钥管理服务注入。

Nginx 应只暴露 443，并把 HTTP 和 WebSocket 都代理给 web 服务；升级请求必须保留：

    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;

使用 Certbot 或云负载均衡器终止 TLS。数据库、Redis 和媒体卷不暴露宿主机端口。

## 编码任务

编写一次恢复演练：备份 PostgreSQL、恢复到空环境、验证文档元数据和向量数量。

## 本地备份

项目使用 PostgreSQL，不使用 SQLite。PowerShell 中执行下面的命令，会导出 PostgreSQL、复制 Docker 媒体卷、压缩为按日期命名的 ZIP，并自动清理 14 天前的备份：

    .\scripts\backup.ps1

可通过 `-RetentionDays 30` 调整保留天数，或通过 `-OutputDirectory D:\backups` 指定备份目录。备份文件内含 `postgres.sql` 和 `media/`；恢复时先在空的 Compose 环境中启动数据库，再将 SQL 导入 PostgreSQL，并将媒体目录复制回 `media_data` 卷。

## 验收清单

- 数据库与媒体卷有独立备份策略
- HTTPS 终止于反向代理
- Worker 崩溃和模型 API 错误可在任务记录中定位

## 常见错误

不要在生产环境暴露 PostgreSQL、Redis 端口；不要使用开发默认密钥。
